# Architecture gates

This module keeps architecture checks separate from production modules.

- `./gradlew checkArchitectureBoundaries` (root task from `build-logic`, letta-mobile-o4ygk.1) reads the module graph that `exportArchitectureGraph` writes to `build/reports/architecture/graph.jsonl` and **fails the build** (required CI via the `test` job) on: any edge into `:app` (except `com.android.test` harnesses that target the APK), feature->feature, shell->shell (`:app`, `:desktop`, `:web`, `:cli`, `:appserver-cli`, `:iroh-wrapper-cli`), library->feature, and multiplatform->single-platform edges. Edges come from every configuration and from `ProjectDependency` objects, so `projects.app` is caught exactly like `project(":app")`. A missing, empty, edgeless or malformed graph fails closed. Known violations live in `android-compose/architecture-tests/boundary-baseline.txt`, one line per edge with an owning bead; a new violation or a stale baseline line fails. `./gradlew :build-logic:test` proves every rule on synthetic graphs and runs a TestKit build that uses `projects.app`.
- `./gradlew :architecture-tests:test` runs fixture tests that prove known source and cycle violations are detected, plus Gradle isolation greps (`SharedLogicIsolationTest`, `SharedUiIsolationTest`).
- `./gradlew :architecture-tests:architectureTest` runs production Konsist source checks (`KotlinSourcePolicy.productionScope`) plus ArchUnit bytecode cycle/layer checks. It depends on `:core:ids:jvmMainClasses` and `:sharedLogic:jvmMainClasses`. **Failures fail the build** (required CI via the `test` job).
- `SharedLayeringTest` (in `architectureTest`, letta-mobile-by4vm.27) fails on a new mutually-importing package pair in sharedLogic `commonMain`+`jvmAndAndroid` or sharedUI `commonMain`, or a new `com.letta.mobile.ui.*` package in sharedLogic, and on stale lines. Known debt lives in `package-cycle-baseline.txt` and `sharedlogic-ui-package-baseline.txt`, which only shrink; see `docs/architecture/shared-layering-ratchet.md`.
- `ChatControllerSurfaceRepositoryArchitectureTest` (in `architectureTest`, letta-mobile-by4vm.80) fails when Android's `AdminChatViewModel` or desktop's `DesktopChatController` gains a public function or property: new chat state goes in sharedLogic behind `TimelineChatSessionPort`. Counts live in `chat-controller-surface-baseline.txt`, which only shrinks (a stale line fails, so lower it in the change that moves a member out).
- `./gradlew advisoryDetekt` runs the Detekt configuration already introduced on main and writes SARIF, XML, and HTML under each participating module's `build/reports/detekt/`. Generated/build/KSP sources are excluded. Detekt remains advisory (`-Parchitecture.strict=true` still promotes Detekt only).

Konsist scans every non-test source set (`*Main`, `jvmAndAndroid`, `main`, Android build-type/flavor sets, `phonePlayground`) and excludes `build`, `generated`, and `ksp` source paths. CommonMain must not import `android.*`, `java.*`, or `javax.*`. ArchUnit imports the compiled `core/ids` and `sharedLogic` JVM surface (former `:core:domain` contract packages), excludes test-fixture packages, checks package-slice cycles, and constrains repository API/model dependencies. `SharedLogicIsolationTest` fails if `:sharedLogic` Gradle-depends on `:app`, `:core:android-data`, `:core:data`, `:core:domain`, `:designsystem`, `:feature-*`, `:desktop`, `:web`, `:sharedUI`, or `:plugin-view`. `PluginViewIsolationTest` fails unless `:plugin-view` depends on exactly `:sharedUI` and `:sharedLogic`. The forbidden list is exhaustive — it mirrors the verbatim `forbiddenProjectDeps` constant in `SharedLogicIsolationTest.kt` and `SharedUiIsolationTest.kt`. Generated classes that compile into the same class directory cannot always be distinguished by bytecode location, so any such finding remains advisory and must be verified against source provenance.
