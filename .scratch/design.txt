A. WHAT SLEEP-TIME IS IN LOCAL-BACKEND LETTA-CODE ("Dreaming" in the 0.34 docs: configuration/memory#dreaming)
1. No sleeptime agent. Each run is an ephemeral background subagent, subagentType "reflection", silent, is_background (L:452442-452452, registered background L:226318). Its model is the parent agent's model on the local backend (resolveSubagentModel L:222952; cloud default letta/auto-memory L:222962). There is no model setting. The legacy Letta REST enable_sleeptime / sleeptime groups do not exist locally (our LocalBackendAgentReader hard-codes enable_sleeptime false, sharedLogic/.../LocalBackendAgentReader.kt:135).
2. Per-agent settings over the wire: get_reflection_settings {request_id, runtime} and set_reflection_settings {request_id, runtime, settings:{trigger, step_count, merge?, merge_instructions?}, scope?} (validators L:261992, L:262002-262006). trigger is off | step-count | compaction-event. step_count is a positive int and is always required. merge is auto | explicit. scope is local_project | global | both (default both, L:437890-437909). Responses carry reflection_settings {agent_id, trigger, step_count, merge, merge_instructions} (L:437944-437998). A successful set also re-emits update_device_status, which always carries reflection_settings (L:204076-204082, null without an agent). Defaults: compaction-event, 25 steps, auto merge (L:202866-202874). Persisted to ~/.letta/settings.json and/or <cwd>/.letta/settings.local.json under reflectionSettingsByAgent[agentId] (L:202813-202865). The TUI /sleeptime is a picker over the same persistence; there is no wire command named sleeptime.
3. Automatic trigger: after a successful turn only (maybeLaunchPostTurnReflection L:451596-451627). compaction-event fires once after a turn with a compaction (also after a manual /compact, L:456743). step-count fires when the assistant steps since the last successful reflection reach step_count (counted from ~/.letta/transcripts, L:450979). No idle trigger. Requires MemFS. Skip reasons: memfs_disabled, retry_backoff, already_active (queued), parent_dirty, no_payload, configuration_error, windows_disabled.
4. WINDOWS GATE: isAutoReflectionEnabled() is false on win32 unless LETTA_ENABLE_WINDOWS_AUTO_REFLECTION=1 (L:451887, O:416017). Our desktop launches the bundled runtime without it (desktop/.../runtime/DesktopLocalRuntimeManager.kt:146-149, DesktopRuntimeLaunchSettings.kt:46-52), so on a Windows desktop automatic dreaming NEVER runs whatever the trigger says. Manual runs bypass the gate.
5. Run now: execute_command with command_id dream, reflect or reflection all go to handleReflectCommand (L:456493-456496). dream is NOT cloud-only on the local backend (requestCloudReflectionRun returns null with localMemfs, L:455810), which corrects the ulcg6 upstream note. Args: only --instruction/-i/-- <text>. The answer comes when the run is launched, not when it finishes: "Started a reflection pass for this conversation." / "...needs the memory filesystem..." / "A reflection agent is already running..." / "No new transcript content to reflect on..." / "Failed to start reflection: ..." (L:456891-456902). Frames: slash_command_start, slash_command_end, execute_command_response. supported_commands lists dream, reflect, reflection on 0.33.6+ (L:203467-203483); the 0.32.3 golden does not.
6. What a run emits: update_subagent_state entries with subagent_type "reflection" (silent, is_background, tool_calls, total_tokens, duration_ms, model); with merge explicit a second general-purpose run with displayType "reflection integration" (L:452207-452222). Memory upkeep workers are subagentType "memory" (silent, L:226304). memory_updated {affected_paths:["*"]} is forwarded to the parent. Completion is an injected user_message <task-notification><summary>Dreamed and made some memories. | Dreamed; no memory changes were needed. | ...</summary> (L:451664-451678, L:452642-452653). There is no reflection_completed frame and reflection is not in background_processes.
7. Results: each run works in a git worktree on branch letta/reflection/<id> and merges with "merge(reflection): <summary>" (L:225579-225595); the subagent commits as "Reflection Subagent" with subject "<type>(reflection): <summary>" plus a crystal-ball emoji and trailers Agent-ID / Parent-Agent-ID (L:106893-106914). memory_history returns {sha, message, timestamp, author_name} (L:263261-263293); letta-code's own TUI marks reflection commits with /\(reflection\)|crystal-ball|reflection:/i (L:500483). So run history = reflection-marked commits in the MemFS log, each with its diff.
8. Experiments: get_experiments / set_experiment exist; reflection_arena is TUI-only (blind A/B of two reflection models), never used by the WebSocket listener. Out of scope here (zxk2n.10 keeps G63).

B. WHAT THE APP EXPOSES TODAY (why it has always been hard to manage)
1. Wire and host exist, nothing calls them: AppServerCommand.GetReflectionSettings/SetReflectionSettings (sharedLogic/.../appserver/AppServerCommand.kt:399-413), client methods (AppServerClient.kt:201-205, 502-506), Iroh reflection.get/reflection.set (sharedLogic/jvmAndAndroid/.../iroh/ReflectionAdminHandlers.kt:21-67). No repository, controller or UI on any platform.
2. The Iroh reflection.set drops merge/merge_instructions, requires conversation_id, and fails without a native client with a message that lacks the capability_unavailable prefix (ReflectionAdminHandlers.kt:24-28,43-57), so a client cannot tell "unsupported" from "failed".
3. The only sleeptime switch in the app is the legacy REST enable_sleeptime: Edit agent LLM card (feature-editagent/.../EditAgentContentList.kt:424-432, saved via EditAgentUseCases.kt:117) and the create dialog (app/.../agentlist/AgentListDialogs.kt:463-467, forced false when local). letta-code ignores it, so the visible toggle is a dead control on every local or Iroh agent.
4. update_device_status.reflection_settings is not parsed (AppServerDeviceStatus.kt; golden letta-code-0.32.3-live.jsonl:9 carries it).
5. No run-now surface: /dream and /reflect exist only as composer slash commands (SlashCommandApi.kt:116-130), with no result surface beyond a status line. No history: MemFS history (MemfsPageHistory.kt) lists reflection commits mixed with everything else, unmarked.
6. Hidden vs visible: SubagentKind.isBackground is only Reflection (sharedLogic/.../model/SubagentKind.kt:26-27); "reflection integration" is covered by the prefix, but memory upkeep runs (subagentType memory, wire label "Memory") show as user subagent chips/rings and in the desktop Background tasks panel (SubagentTaskProjection.kt:23).
7. Nothing shows that a dream is running: presence derives only from run phases (presence/ConversationRunRegistry.kt:85-106); the mascot never shows it. No notification exists for a finished dream (NotificationDeliveryCoordinator.kt:39-63 has no per-agent opt-in).
8. Embedded Android (0.26.1): supported_commands lacks dream/reflect and reflection settings may be absent; nothing tells the user why.

C. THE UX THE USER NEEDS (one shared "Dreaming" surface, phone and desktop)
- Per agent: Dreaming on/off, when (after N steps, or when the conversation is compacted), "agent reviews before applying" (merge explicit) with optional instructions, and where the setting is saved (this project, everywhere, both). Model shown read-only: "uses the agent's model".
- Status: running now (from the subagent registry: elapsed, tool calls), last dream (time, summary), trigger explained in words, and the honest blocker when there is one (Windows auto gate, MemFS off, unsupported host) with a fix where we own it (desktop opt-in for the Windows gate).
- Run now (optional instruction), with letta-code's own answer shown.
- History: reflection commits newest first, each opening its diff (files touched, +/- counts, sha).
- Notify when a dream finishes (opt-in, per agent, off by default).
- Desktop mascot dozes (SLEEPING pose) while its agent dreams and is otherwise idle.
- Unsupported host: one clear reason (embedded 0.26.1 runtime; Iroh host without the relay -> update the wrapper).
- Dream/reflection/memory runs never appear as user subagent chips; they are visible only in the Dreaming surface.
